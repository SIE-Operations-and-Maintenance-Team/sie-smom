# PostgreSQL 建表规范

## 一、表结构通用模板

所有业务表均继承自 `DataEntity`，必须包含以下**默认列**：

```sql
CREATE TABLE example_bill (
    -- ========== 基础字段（DataEntity 继承） ==========
    id            BIGINT          GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,  -- 主键ID（对应 C# double）
    sync_id       BIGINT          NOT NULL,                                      -- 同步ID
    create_by     BIGINT,                                                        -- 创建人ID
    create_date   TIMESTAMP       NOT NULL,                                      -- 创建时间
    update_by     BIGINT,                                                        -- 更新人ID
    update_date   TIMESTAMP       NOT NULL,                                      -- 更新时间
    inv_org_id    INT,                                                           -- 所属机构ID
    is_phantom    BOOLEAN         NOT NULL DEFAULT FALSE,                        -- 假删标记（FALSE=否, TRUE=是）

    -- ========== 业务字段（视需求添加） ==========
    no            VARCHAR(80),                                                   -- 单据号（若需要）
    status        INT                                                            -- 状态枚举（若有）
    -- ... 其他业务字段 ...
);
```

> **⚠️ 标识符大小写**：PostgreSQL 将**未加双引号**的标识符折叠为小写。上例使用小写标识符（`id`、`sync_id`）建表，则查询/INSERT 时也必须写小写；若沿用 SMOM 惯例用大写列名，则建表时需**双引号包裹**（如 `"ID" BIGINT ...`），查询时同样必须始终带双引号。**同一库内二选一，禁止混用**（见 `references/16-postgresql-query.md` 10.6）。

## 二、ID 生成策略

### 1. 推荐：IDENTITY 自增主键（PostgreSQL 10+）

```sql
id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

- 插入时**不写入 id 列**，由数据库自动生成，无需显式取序列值。
- 使用 `BY DEFAULT` 而非 `ALWAYS`：允许显式指定 ID（历史数据迁移、跨库同步场景需要）。
- 与 MSSQL/Oracle 规范"序列生成"的差异：MSSQL 用 `CREATE SEQUENCE` + `NEXT VALUE FOR`，Oracle 用 `CREATE SEQUENCE` + `.NEXTVAL`，PostgreSQL 用 `IDENTITY` 即可，**无需单独建序列**（底层自动创建隐藏序列）。

### 2. 若沿用"显式序列"习惯（与 MSSQL/Oracle 规范一致）

```sql
-- 自定义序列
CREATE SEQUENCE seq_example_bill_id START WITH 100000;
CREATE SEQUENCE seq_example_bill_sync_id START WITH 1;

-- 插入时显式取序列值（等价于 Oracle SEQ.NEXTVAL）
INSERT INTO example_bill (id, sync_id, ...)
VALUES (nextval('seq_example_bill_id'), nextval('seq_example_bill_sync_id'), ...);
```

### 3. SERIAL 伪类型（旧写法，不推荐新建表使用）

```sql
id BIGSERIAL PRIMARY KEY   -- 等价于 id BIGINT NOT NULL DEFAULT nextval('example_bill_id_seq')
```

> **建议**：新建 PostgreSQL 表优先采用 `GENERATED BY DEFAULT AS IDENTITY`（第 1 种方式）；若项目要求与 MSSQL/Oracle 保持一致的"显式序列"行为，则用第 2 种方式并在应用层管理取号。

## 三、字段类型映射规则

| C# 类型 | PostgreSQL 类型 | 说明 |
|---------|-----------------|------|
| `double` / `double?` | `BIGINT` | 主键、外键ID（对应 MSSQL `FLOAT` / Oracle `NUMBER(18,0)` / MySQL `BIGINT`，PostgreSQL 为精确整数） |
| `int` / `enum` | `INT`（`INTEGER`） | 枚举值、状态码（对应 Oracle `NUMBER(10,0)`） |
| `string`（单据号/用户名） | `VARCHAR(80)` | 短文本，按需调整长度 |
| `string`（URL/长文本） | `VARCHAR(4000)` | 长文本（或 `TEXT` 根据场景，`TEXT` 无长度限制） |
| `decimal` | `NUMERIC(18,6)` | 金额、数量等精确值（别名 `DECIMAL`） |
| `DateTime` | `TIMESTAMP` | 日期时间（精确到微秒；`TIMESTAMP` 无时区，若需带时区用 `TIMESTAMPTZ`） |
| `bool` | `BOOLEAN` | 布尔值（`TRUE` / `FALSE`，对应 MSSQL `BIT` / Oracle `NUMBER(1,0)` / MySQL `TINYINT(1)`） |
| `float` | `DOUBLE PRECISION` | 业务浮点，尽量避免用于金额等精确场景 |

## 四、命名规范

### 表名
- 全大写，下划线分隔（未加引号建表时实际存储为小写）
- 示例：`OQC_SHIP_INSP_CONFIRM_BILL`
- 表名应体现业务含义及所属模块

### 列名
- 全大写，下划线分隔
- 避免使用 PostgreSQL 保留字（如 `USER`、`ORDER`、`GROUP` 等），必要时用双引号包裹
- 外键字段建议包含 `_ID` 后缀
- 枚举字段建议包含状态含义的后缀或前缀

### 主键
- 主键列统一命名为 `ID`，类型 `BIGINT`，`PRIMARY KEY (ID)`

### 索引
- 格式：`IX_表名_字段名`

### CHECK约束
- 格式：`CHK_表名_字段名`

## 五、必加的操作

### 1. 添加表备注

```sql
-- 建表后追加
COMMENT ON TABLE example_bill IS '表中文注释';
```

### 2. 添加字段备注

```sql
-- 逐列添加（与 Oracle 的 COMMENT ON COLUMN 语法一致）
COMMENT ON COLUMN example_bill.id IS '主键ID';
COMMENT ON COLUMN example_bill.no IS '单据号';
```

> **注意**：PostgreSQL **不支持** MySQL 建表内联 `COMMENT '...'` 语法，必须在建表后用 `COMMENT ON` 语句追加。

### 3. （推荐）添加CHECK约束（枚举字段）

```sql
-- PostgreSQL 原生强制校验 CHECK 约束（MySQL 需 8.0.16+）
ALTER TABLE example_bill
ADD CONSTRAINT chk_example_bill_status
CHECK (status IN (0, 1, 2, ...));  -- 对应枚举所有合法值
```

### 4. （推荐）添加索引

```sql
-- 单据号索引（高频查询）
CREATE INDEX ix_example_bill_no
ON example_bill (no);

-- 外键索引（关联查询）
CREATE INDEX ix_example_bill_ref_id
ON example_bill (ref_id_field);
```

## 六、完整建表示例（模板）

```sql
-- =============================================
-- 创建表：example_bill
-- 描述：示例业务单据表
-- 数据库：PostgreSQL 10+（IDENTITY 需要 10+）
-- =============================================

-- 1. 建表（未加引号，标识符存储为小写）
CREATE TABLE example_bill (
    -- 基础字段（DataEntity）
    id            BIGINT          GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sync_id       BIGINT          NOT NULL,
    create_by     BIGINT,
    create_date   TIMESTAMP       NOT NULL,
    update_by     BIGINT,
    update_date   TIMESTAMP       NOT NULL,
    inv_org_id    INT,
    is_phantom    BOOLEAN         NOT NULL DEFAULT FALSE,

    -- 业务字段
    no            VARCHAR(80),
    bill_type     VARCHAR(40),
    status        INT,
    qty           NUMERIC(18,6),
    amount        NUMERIC(18,6),
    remark        VARCHAR(4000),
    bill_date     TIMESTAMP,

    -- 外键字段
    work_order_id BIGINT,
    material_id   BIGINT
);

-- 2. 表备注
COMMENT ON TABLE example_bill IS '示例业务单据表';

-- 3. 字段备注
COMMENT ON COLUMN example_bill.id IS '主键ID';
COMMENT ON COLUMN example_bill.sync_id IS '同步ID';
COMMENT ON COLUMN example_bill.create_by IS '创建人ID';
COMMENT ON COLUMN example_bill.create_date IS '创建时间';
COMMENT ON COLUMN example_bill.update_by IS '更新人ID';
COMMENT ON COLUMN example_bill.update_date IS '更新时间';
COMMENT ON COLUMN example_bill.inv_org_id IS '所属机构ID';
COMMENT ON COLUMN example_bill.is_phantom IS '虚体标记(FALSE=否,TRUE=是)';
COMMENT ON COLUMN example_bill.no IS '单据号';
COMMENT ON COLUMN example_bill.bill_type IS '单据类型';
COMMENT ON COLUMN example_bill.status IS '状态(0=草稿,1=已提交,2=已审核)';
COMMENT ON COLUMN example_bill.qty IS '数量';
COMMENT ON COLUMN example_bill.amount IS '金额';
COMMENT ON COLUMN example_bill.remark IS '备注';
COMMENT ON COLUMN example_bill.bill_date IS '单据日期';
COMMENT ON COLUMN example_bill.work_order_id IS '工单ID(引用WorkOrder)';
COMMENT ON COLUMN example_bill.material_id IS '物料ID(引用Material)';

-- 4. （可选）IDENTITY 起始值设为 100000，避免与历史数据冲突
ALTER TABLE example_bill ALTER COLUMN id RESTART WITH 100000;

-- 5. 创建索引
CREATE INDEX ix_example_bill_no ON example_bill (no);
CREATE INDEX ix_example_bill_status ON example_bill (status);
CREATE INDEX ix_example_bill_work_order ON example_bill (work_order_id);

-- 6. （可选）枚举字段CHECK约束（原生强制校验）
ALTER TABLE example_bill
ADD CONSTRAINT chk_example_bill_status
CHECK (status IN (0, 1, 2));
```

> **⚠️ IDENTITY 起始值**：`GENERATED BY DEFAULT AS IDENTITY` 默认从 1 开始。若需从 100000 开始（与 MSSQL/Oracle 规范一致），建表后执行 `ALTER TABLE ... ALTER COLUMN id RESTART WITH 100000`，或在建表语句中指定 `START WITH 100000`（`GENERATED BY DEFAULT AS IDENTITY (START WITH 100000)`）。

## 七、从C#实体到PostgreSQL表的快速映射

当给出一个C#实体类时，按以下步骤转换：

1. **提取`DataEntity`默认字段** → 映射为基础列
   - `ID` → `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`（主键）
   - `SYNC_ID` → `BIGINT NOT NULL`
   - `CREATE_BY` → `BIGINT NULL`
   - `CREATE_DATE` → `TIMESTAMP NOT NULL`
   - `UPDATE_BY` → `BIGINT NULL`
   - `UPDATE_DATE` → `TIMESTAMP NOT NULL`
   - `INV_ORG_ID` → `INT NULL`
   - `IS_PHANTOM` → `BOOLEAN NOT NULL DEFAULT FALSE`

2. **提取业务属性**（Property字段）：
   - `string` → `VARCHAR(长度)`，默认80或4000
   - `int`/`enum` → `INT`
   - `float`/`double` → `DOUBLE PRECISION`
   - `decimal` → `NUMERIC(18,6)`
   - `DateTime` → `TIMESTAMP`

3. **提取引用类型**（IRefIdProperty）→ 映射为 `BIGINT` 外键字段

4. **解析`[Label]`** → 生成 `COMMENT ON COLUMN` 备注

5. **检查`MapTable`配置** → 确定表名

6. **检查`HasIndex`** → 生成索引

7. **标识符大小写** → 建表与查询保持同一风格（未加引号小写 或 双引号大写，二选一）
